# 咖啡记录要求与判定规则

## 文件分工

- `records/duanz-coffee-log.md`：唯一固定记录文件，只追加真实萃取记录、设备实测和已验证配方。
- `references/measurement-template.md`：每杯记录时使用的字段模板，不存历史数据。
- `references/recording-requirements.md`：本文件，规定如何记录、如何判断、如何给下一杯建议。
- `references/espresso-troubleshooting.md`：机器故障排查参考，不代替设备实测。
- `profiles/duanz-coffee-setup.md`：设备与当前基线摘要，不作为逐杯日志。

## 记录原则

1. 用户口述后，直接追加到固定记录 `records/duanz-coffee-log.md`；不要要求用户手填。
2. 用户没有说的字段写「未记录」，不凭经验补数。
3. 先记录事实，再做判断；明确区分「实测」「用户感受」「推断」。
4. 旧刻度和当前刻度分开。当前 Bricks 01S 必须使用 `2.4/1` 这类写法；历史 `2.8/2.9` 只保留为低置信相对记录。
5. 每杯最多改变一个变量。若用户已经同时改变多个变量，记录为「多变量，不能归因」，不强行得出单变量结论。
6. 参数要写单位：g、s、°C、bar；粉液比统一写 `出液 ÷ 粉量`。
7. 机器问题先于风味问题判断：先看空放流量、盲碗压力、水路和粉饼，再谈磨度与配方。
8. 未经复测的结论标为「待验证」，不能写成「已解决」或「必须更换」。

## 每杯最少字段

- 日期、饮品
- 豆子与豆子状态；烘焙日期不清楚就写未记录
- 粉量、研磨、出液、总时间
- 温度、压力、P1/P2（不知道就写未记录）
- 是否无底手柄、WDT/布粉情况
- 牛奶/椰子水/冰的用量
- 入口、中段、后味
- 喷溅情况、评分
- 判断和下一杯只改一个变量

## 问题层级

### 设备层

- 空放流量低：先查水箱、进水软管、进水滤网、泄流阀、水路；再考虑泵。
- 盲碗无法约4秒到10bar：查 OPV、泄流阀、泵和水路。
- 空放和盲碗均正常，但带粉建压慢：优先查研磨、粉量、粉饼、布粉和 P1/P2。
- 喷溅：先查结块、WDT、布粉、粉量、粉碗和密封；不能直接归因于泵。

### 萃取层

- 高压 + 流速慢：可能太细、粉量多、粉饼过厚或 OPV 设置问题。
- 低压 + 流速快：可能太粗、粉量少、通道或 OPV 设置问题。
- 苦涩：可能过萃、局部通道、老豆氧化或浓度过高；先结合压力曲线和味道判断。
- 苦醇但后味干净：优先怀疑浓度偏高；先只增加出液或减少粉量，不同时改研磨。
- 酸薄：可能欠萃或浓度不足；下一杯只选细磨、减出液或升温中的一个。

## 公式与使用边界

### 粉液比

```text
R = 出液重量 / 干粉重量
```

例如 18g 粉、43.7g 出液：`R = 43.7 / 18 = 2.43`，记作 `1:2.43`。

### TDS 方向

```text
TDS ≈ 萃取物重量 / 饮品重量
```

若没有折光仪，不写实测 TDS；只能说「方向上浓度可能更高/更低」。不能用粉液比直接冒充萃取率。

### 萃取率

```text
EY = TDS × 饮品重量 / 干粉重量
```

必须有 TDS 测量才可计算实测 EY。没有 TDS 时，历史记录只写「未测」，不把经验估算写成事实。

### 粉饼阻力的定性模型

```text
R(t) = Rmax × (a + (1-a) × e^(-t/τ))
```

它只用于理解阻力随萃取过程变化，不用于凭几项参数反推机器故障或真实萃取率。

## 配方沉淀等级

- **历史记录**：只证明做过，不证明可复现。
- **阶段基准**：味道好且参数完整，但可能同时改过多个变量。
- **已验证配方**：至少重复两次，关键参数一致，味道方向一致，且没有明显设备异常。

当前 18g / 旧记2.9 / 43.7g / 25s / 91°C / 290g热奶是「阶段最佳」，不是完成单变量验证的配方。

## 输出要求

每次口述记录后按以下顺序回复：

1. 一句话确认已记录。
2. 参数事实和缺失字段。
3. 问题层级判断，并标注置信度：高/中/低。
4. 与历史基准的变化。
5. 下一杯只改一个变量，并给出保持不变的字段。
6. 若记录形成重复好结果，询问是否升级为已验证配方；不要自行升级。
