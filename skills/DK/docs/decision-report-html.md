# 决策报告 HTML 输出规范（交互式决策台）

> 当决策/选品涉及 2 项及以上方案对比、权衡或需要用户做选择时，**一律生成本地交互式决策台 HTML 页面**（基于 `~/.pi/agent/templates/decision-deck-template.html`），禁止部署公网，只放本地。

## 触发与产物

- **触发**：任何涉及 2 项及以上候选选品、方案取舍、购物对比的场景。
- **产物位置**：当前工作目录的 `docs/DK-决策台-<主题>.html` 或 `$HOME/workspace/docs/`。
- **页面必备功能**：
  1. 卡片式预设选项（标明立即做 / 需权衡 / 需给信息，带代价与推荐理由）。
  2. 显式提供「其他（我自己指定）」输入卡。
  3. 支持动态「+ 增加全新事项」卡片。
  4. 底部实时 Markdown 预览与一键复制开工提示词。
- **回复规范**：回复第一句给结论，给出本地文件的可点绝对路径 `[决策台](/home/duanz/...)`，供用户在浏览器中打开使用。

## 硬规则（违反即返工）

1. **零外部依赖**：不引 CDN、不引 JS 库、不引外部字体。图表一律纯 CSS 条形 + 内联 SVG。
   （离线可开、minis:// 预览可用、永远没有"图挂了"的 bug）
2. **视觉语言与 gushen 报告一致**（用户已认可的暗色终端风，勿另起炉灶）：
   bg `#0b0e13` / surface `#12161f` / surface-2 `#171c27` / 单一琥珀强调 `#e8b04b`
   / 推荐=红系 `#ff4d5e` / 否决=绿系 `#00c767`（沿用 gushen 红正绿负语义：
   红=行动/推荐，绿=出局/否决）/ 圆角 10px / 数字全部 `.num`（tabular-nums）
3. **禁 emoji 图标、禁紫蓝 AI 渐变**；图标用文字标签或 CSS/SVG
4. **响应式不溢出**：viewport meta 必须有；宽表格外包 `overflow-x:auto` 容器；
   不用固定像素宽度布局
5. **数据同源**：页面里每个数字都必须能在 Markdown 推演报告中找到出处；
   VETO 候选必须出现在对比表中并标明否决原因（不许静默删除）

## 页面结构（自上而下）

```
masthead   eyebrow(DK DECISION) + 大标题 + 状态 pill(已过独立验证/待验证) + lede 一句话结论
verdict    结论带：推荐方案 + 一句话理由 + 翻盘条件
candidates 候选卡片行：每卡 = 名称/价位/判定标签(推荐·备选·暂缓·否决)
compare    决策关键参数横向对比表（含被 VETO 的候选；否举行红色高亮）
charts     图表区：价格带横向条形图 + 多维度评分条形图（0-5 分，评分依据写进脚注）
chain      思维链 ①安全→⑤可得性 摘要（每步 ✓/✗ + 一句话）
voices     评论区真实声音摘录（反恰饭层，注明来源视频/平台）
actions    行动清单（编号步骤，可直接执行）
footer     证据来源列表 + 数据日期 + 置信度声明
```

## 防 bug 自检（生成后必做）

- [ ] 浏览器实际打开截图过一遍（browser_use navigate → minis:// 路径），不是"应该没问题"
- [ ] 手机宽度（~400px）与桌面宽度各看一次，无横向溢出、无文字截断
- [ ] 所有百分比条宽度加起来 ≤100%（分组条按容器内占比算）
- [ ] **网格容器的每个子元素都要数一遍**：grid 子元素（含 ::before）会自动按行填充，
  多出来的子元素会掉进下一行的窄列里（实测案例：行动清单的副文掉进 26px 序号列）。
  多行内容用显式 `grid-column` 定位
- [ ] 特殊字符（& < >）已转义，评论区引号内容原样呈现不破版
