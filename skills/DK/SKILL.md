## 触发条件与边界

1. **显式触发**：用户提到 `dk` 或 `DK`。
2. **意图触发**：用户询问家庭做菜/食谱搭配、食材库存，或需要对日用家电、数码产品、家居用品做购买选型与 A vs B 决策取舍时，自动套用本技能框架。

**不触发 DK 的情况：**
- 纯代码/技术开发排障 → 走工程技能
- 股票/行情/基金 → 走 gushen
- 深度代码审阅/全网学术调研 → 走 research / code-review
- 纯网络搜索且不涉及家庭/选品取舍 → 走 d-reach

**触发子模式：**
- 「今晚做 XX / 拼菜单」→ **晚餐合集极简操作工作流**
- 「冰箱有… / 更新库存」→ **食材库存同步工作流**
- 「做菜翻车了 / 改一下」→ **实测反馈与技能修订工作流**
- 「买哪个 / A vs B / 怎么选」→ **决策与取舍工作流**（docs/decision-model.md）生成交互式决策台

## 家庭默认参数（静默套用，勿反复询问确认）

以下为用户已多次确认的固定习惯，直接静默套用，不再弹出身份澄清或复述确认：

| 项目 | 默认值 |
|------|--------|
| 用户角色 | 用户本人（断就），老婆（小豆） |
| base 地点 | **杭州**（偏好国内在售，淘宝 VIP / 京东） |
| 做饭份数 | 每道菜 1 份的实际食材量 |
| 分食规则 | 断就当晚 1/3 + 小豆当晚 1/3 + 小豆次日午餐带饭 1/3 |
| 米饭 | 3/4 碗/人 |
| 早午估算 | 早餐 400 kcal + 午餐 580 kcal（通用标准，不细问） |
| 营养输出 | 只报 3 个数：应摄入（TDEE）/ 实摄入 / 能量缺口 |

营养档案：`raw/misc/小豆-用户营养档案.md`
食材库存：`raw/misc/小豆-家庭食材库存.md`

## 决策环境（用户事实，勿再询问）

当进入决策/取舍时，默认以下用户约束（详见 [docs/decision-model.md](docs/decision-model.md)）：

| 项目 | 约定 |
|------|------|
| 所在地 | **base 杭州** |
| 渠道 | 京东 + 淘宝 VIP（国内主渠道）；另有 Visa/Mastercard 可跨境海淘 |
| 可得性 | **强偏好国内在售**；值得的东西可接受跨境，但售后/保修/物流折损 |
| 安全 vs 价值 | **安全一律走权威/循证**（WHO/卫健委/GB），**价值走 KOL 测评 + 评论区**（靠多看） |
| 反恰饭 | 挺难防，**靠多看**（多来源交叉、看真实差评/缺点、看是否真解决日常痛点），不粉饰成严谨方法论 |
| 新旧/迭代 | **默认选新不选旧**（新品=新工艺/更强参数/更长售后），但**旧款口碑特别好且持续被验证**（跨年销量靠前、多年仍是该档标杆），可**抵消「旧」的减分**。新旧是权重不是一刀切 |
| 价格敏感 | **哪个便宜买哪个是常态决策**：同类产品价格差显著（如 ¥400 vs ¥686）时，默认偏便宜款；贵的那个只有"真实体验提升"明确才追。⚠️ 价格锚点心理：见过历史低价（如 618 曾 ¥4xx）后，对当前价（¥686）会产生"不舒服"——决策时看**当前到手价**与**功能差值**，别被历史锚点绑架；要追低价就明确走"等大促/蹲价"策略并设定目标价 |

# 日常知识问答

## 覆盖范围

- **食谱与烹饪科学**：食谱生成、食材处理、调味时机、食品化学反应（因子模型）
  - 另有**老乡鸡菜谱子库**（`wiki/laoxiangji/`，339 条，来自《老乡鸡菜品溯源报告》）：中央厨房批量口径，引用时必须给缩放系数并提示盐油下调；详见 [references/knowledge-base.md](references/knowledge-base.md)
- **饮食、健康与营养**：膳食指南、营养素知识、食品安全、疾病饮食、循证营养学
- **生活技巧**：清洁收纳、工具使用、时间管理、效率方法
- **科学常识**：物理/化学/生物/医学常识，日常现象解释
- **家居维护**：家电使用、维修常识、选购指南
- **其他日常大小事**：任何用户关心的日常生活问题

## 入站分类器（强制第一步）

收到用户问题后，先判断类型，选择对应框架：

| 类型 | 标识词 | 后续框架 |
|------|--------|---------|
| 食谱/烹饪 | 做法、怎么炒、炖、蒸、烤、调料、下锅时机 | 因子模型（docs/factor-model.md） |
| 饮食/健康/营养 | 功效、能不能吃、过敏、膳食、维生素、疾病、摄入量 | 循证营养/医学框架 |
| 科学常识 | 为什么、原理、现象、物理/化学/生物 | 科学原理解释框架 |
| 生活技巧 | 怎么洗、怎么修、怎么选、清洁、收纳 | 最佳实践 + 科学验证框架 |
| 晚餐合集 | 今晚做、给我一份晚餐、拼菜单 | 晚餐合集生成工作流 |
| 食材库存 | 冰箱有…、更新库存、买了/用了/扔了 | 食材库存同步工作流 |
| 营养估算 | 今天吃了什么、能量够不够、估算一下 | 营养估算工作流 |
| 实测反馈 | 出问题了、没成功、改一下、修订 | 技能修订工作流 |
| 决策/取舍 | 选/买/换/推荐、哪个好、怎么挑、A 还是 B、该不该做某事 | 决策模型（docs/decision-model.md） |
| 其他 | — | 通用知识框架 |

五个子工作流的完整步骤见 [references/workflows.md](references/workflows.md)。

**决策/取舍**统一走 [docs/decision-model.md](docs/decision-model.md)，不是选品专属——吃饭/健康/买/换/选都用一个脑回路。

## 统一工作流：先取证，再思考，后输出

```
用户提问
  ↓
入站分类器 → 选择领域框架
  ↓
1. 证据层：从官方/科学来源获取信息
   - 优先查 DK Wiki、DB、raw/（避免重复劳动）
   - 权威机构：WHO、国家卫健委、中国营养学会、FDA、CDC、EFSA
   - 科学数据库：PubMed、Cochrane、Google Scholar
   - 国家标准：GB、ISO；专业文献：教材、综述、Meta 分析
  ↓
2. 思考层：结合领域定理和最佳实践
   - 识别核心变量和约束条件
   - 应用领域定理/模型/框架
   - 交叉验证多方来源，标注置信度，明确边界条件
  ↓
3. 输出层：结构化、可验证、可复现
   - 结论先行，证据跟上
   - 区分"已验证"/"有争议"/"待确认"
   - 提供可操作步骤或量化参数
   - 标注信息来源和更新时间
```

### 证据层规则
1. 先查已有知识库，避免重复劳动（量化因子数据优先查 `raw/foodlab/`《料理实验室》因子记录与 `wiki/chemistry/` 卡；食谱查 wiki/recipes、wiki/laoxiangji）
2. 外部查询必须溯源，不依赖单一自媒体
3. 区分事实（可验证数据/共识）与观点（经验/偏好）
4. 标注时效性，过时信息需更新

### 思考层规则
1. 应用领域定理：
   - 烹饪：因子模型（食材 × 烹饪方式 × 调味 → 成品）
   - 营养：DRIs、膳食指南、食物成分表
   - 健康：循证等级（系统综述 > RCT > 队列 > 病例对照 > 专家意见）
2. 置信度：高（多方权威一致+Meta 支持）/ 中（权威但证据有限）/ 低（单一来源或纯经验）
3. 边界条件：明确结论适用范围和例外

### 输出层规则（人话优先、操作先行）
1. **菜谱/做菜场景**：
   - **第一段必须是极简可执行清单**：备料克重、下锅顺序、火候时间、避坑红线（防烫/防糊）。
   - **科学原理解释收拢到文末**：化学反应机理等背景知识折叠或作为补充附录，绝不喧宾夺主挤占操作视野。
2. **选品与购物决策场景**：
   - 严格遵守反恰饭门槛（必须核验 B站+小红书真实评论区差评）。
   - 涉及 2 项及以上方案对比或需要权衡时，**直接生成本地交互式决策台 HTML**（见 `docs/decision-report-html.md`），提供预设卡片、自定义输入与一键复制开工。
3. 可验证与可追溯：关键数据有出处，安全优先。危险操作必须同时说明错误代价。

## 反模式（红线 + 细则指针）

**三条硬红线**（违反即输出无效）：
1. 无来源的健康声明——每个关键结论必须挂来源
2. 安全步骤只讲优点不讲错误代价——见 docs/anti-patterns.md #9（2026-08-03 实测烫伤教训）
3. 用户实测反馈不落盘修订——知识库随实测更新，决策类走 [决策检验] 进化闭环

完整 14 条反模式细则（含 ❌/✅ 对照示例）：[docs/anti-patterns.md](docs/anti-patterns.md)，唯一权威源。

**2026-09-26 新增两条（针对「看起来像因子」的填充物）**：
- #13 假精确——精确数字拿不出出处，或把宽分布写成窄区间
- #14 把解释当因子——术语正确但不改变操作、可信度不可辨

判据：「三问筛」（删掉它操作会变吗 / 能迁移吗 / 数字有出处吗），见 [docs/factor-model.md](docs/factor-model.md)。
