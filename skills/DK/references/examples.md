# DK 使用示例

> 八个典型场景的完整输入输出示例。

## 使用示例

### 示例1：食谱/烹饪类（因子模型）
```
用户：番茄怎么做好吃？

Agent：
1. 入站分类：食谱/烹饪 → 因子模型
2. 取证：查询 Wiki 找到 [[番茄]] 页面、相关食谱 [[番茄炒蛋]] [[番茄蛋汤]]
3. 因子分析：
   - 食材因子：番茄含番茄红素（脂溶性）、水分>90%、pH≈4.5（酸性）
   - 烹饪方式：炒/炖（油传导促进番茄红素溶出）、凉拌（保留维生素C）
   - 调味因子：盐后放（减少渗透压出水）、糖平衡酸味
4. 输出：完整回答 + 置信度标注
```

### 示例2：科学常识类（科学方法框架）
```
用户：美拉德反应是什么？

Agent：
1. 入站分类：科学常识 → 科学方法框架
2. 取证：查询 Wiki [[美拉德反应]]，必要时查权威来源
3. 思考：反应条件（140-165°C）、反应物（氨基酸+还原糖）、生成物（类黑精+风味物质）
4. 输出：反应机理 + 烹饪应用 + 健康影响 + 安全边界
```

### 示例3：饮食/健康/营养类（循证框架）
```
用户：每天应该走多少步？

Agent：
1. 入站分类：饮食/健康/营养 → 循证框架
2. 取证：WHO/国家卫健委建议，PubMed 研究数据
3. 思考：证据等级评估（RCT vs 队列研究），剂量-效应关系，人群差异
4. 输出：建议值（如 6000-10000 步）+ 证据来源 + 置信度 + 适用人群边界
```

### 示例4：营养分析
```
用户：这道菜的营养成分是什么？

Agent：
1. 入站分类：饮食/健康/营养 → 循证框架
2. 取证：查询 Wiki 相关食材页面 + 食物成分表
3. 计算：汇总各食材营养成分（考虑烹饪损耗系数）
4. 输出：营养成分表 + 健康建议 + 置信度标注
```

### 示例7：实测反馈 → 技能修订
```
用户：今天做醋溜豆芽，按你的步骤被油溅了一身，烫伤了。

Agent：
1. 入站分类：实测反馈 → 技能修订工作流
2. 复盘事故链：200°C → 爆香料（干辣椒花椒）→ 直接沿锅边淋醋 → 油花四溅 → 烫伤
3. 定位根因：菜谱忽略了「醋含水 90%」「200°C 危险温度」「站位防护」3 个因子
4. 影响范围：所有含液体调料的菜（醋/料酒/酱油/啤酒）
5. 修订：新建 wiki/techniques/防溅油.md；修订 调味料下锅时机.md 和 醋溜绿豆芽.md；
   重新生成相关 HTML；更新合集页
6. 置信度升级：低 → 高 [实战检验 2026-08-03]
7. 给用户诊断报告（🔍诊断 / 📝修订 / ✅升级）+ 落盘结果
```

### 示例8：决策/取舍 → 决策模型（含进化闭环）
```
用户：想买个磨豆机，家里早餐手冲用，预算 1000 上下。

Agent：
1. 入站分类：决策/取舍 → 决策模型（docs/decision-model.md）

2. 决策漏斗（先砍范围）：
   - ① 地域：base 杭州，优先国内在售（京东/淘宝能买）
   - ② 预算带：1000 上下（价格是约束）
   - ③ 市场验证：京东/淘宝「手冲磨豆机」销量+好评 TOP → 用钱投票
   - ④ 人群共识：什么值得买 / B站 测评榜 → 幸存 5-8 个

3. 决策关键参数表（只抓影响真实体验的）：
   磨盘材质 / 研磨均匀度 / 电机功率+噪音 / 清洁难易 / 刀头结构

4. 金字塔取证（标称 vs 实测分离）：
   - 官方：官网标称「研磨均匀度 95%」
   - 博主实测：B站测评实测出粉「实际均匀 82%」→ 标称 vs 实测偏差
   - 评论区：真实痛点「刷刀头麻烦」

5. 完整思维链（每候选跑 ①→⑤）：
   - 安全 VETO：无食品安全/用电风险 → ✓
   - 价值判断：多花的钱能否换【真实体验提升】？（均匀度是否真提升 → 是 → 买贵值得）
   - 频率触发器：早餐天天用 → 高频离不开 → 进入②
   - 信号集：参数/体验/技术/口碑 → 博主测评+评论区交叉，恰饭风险「中」
   - 地域可得性：国内在售 → ✓

6. 多角度候选方案 + 明确推荐：
   🧭 需求：早餐手冲，双人（断就+小豆），高频，预算1000
   📋 方案A（一步到位）…… / 方案B（省心够用）…… / 方案C（性价比）……
   🎯 推荐 [方案A]，一句话理由 + 什么情况下会翻到方案B

7. 进化闭环（关键）：
   用户给真实思路：其实我更看重「出粉一致性」，且我只用浅烘豆；
   用户最终决定：选了 [方案B]（比推荐低一档）。
   → DK 对比：我的链把「深度/浅烘适配」漏判为一个关键变量
   → 调整规则：价值判断里加入「适配用户实际烘焙深度」这一项
   → 链条进化 + 标 [决策检验 2026-08-26]
   （若 DK 有道理，也可反过来「劝」用户，指出其取舍风险）
```
