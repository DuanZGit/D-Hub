# Explain Up

解释有个**形态阶梯**：默认谁都会停在最低一档（markdown 段落），这个技能负责**按内容的形状往上选一档**。
最高的那一档（自播放讲解页）是 Karpathy 说的「讲解视频」的落地替代 —— 拿到时间维度，不碰 ffmpeg 和 TTS。

## 阶梯

停在**第一档装得下的地方**。多挂一档是负担，不是本事。

| 档 | 形态 | 什么时候停在这 |
|---|---|---|
| L0 | 段落 | 一段话能说完 → **只在对话里** |
| L1 | 受控语言 | 内容是一条线，但用户说「看不懂 / 说人话」 → 只在对话里 |
| L2 | 图 | ≥3 个相连部分：流程、层级、依赖、时序、状态 → 对话内图或 `.svg` |
| L3 | 交互页 | 要反复查、对照：4+ 行表格、多方案、长清单 → 单个 `.html` |
| L4 | 自播放讲解页 | 从零讲清一个机制**怎么运转**：≥5 个阶段且有先后 → 单个 `.html`，打开自己演 |

**判到 L3/L4，产出就是 `.html` 文件**，对话里只给结论和路径。用户要的是能一口气看完的东西，不是在聊天框里读长表格。

## 什么时候才升（含刹车）

升之前两道都得过：

1. **用户要的是理解，不是答案** —— 「解释 / 讲清楚 / 帮我理解 / 怎么运作 / 为什么 / 阅读理解」
2. **内容确实有形状** —— 拿掉形态只剩一串并列事实的不算

L0→L1 只要第 1 条；L2 起两条都要。刹车：

- **排错现场不升**：用户在等结论、手上有报错时停在 L0/L1。
- **说过一次「别画」**，本次会话不再升到 L2 以上。
- **升级 ≠ 加长**：L4 场景 5–9 个，超了拆两页；一屏一个意思，塞满就没人重读。
- L2 起仍要守 `diagram` 自己的绘图纪律（该画才画，一个事实不成图）。

### L3/L4 的门：自己判，不要回头问

升到 L3/L4 前，在心里过三件事：**讲给谁、他读完该带走的那一个洞察、先讲什么后讲什么**。
这三件事从用户给的上下文里基本都能推出来。

**默认直接做完给成品** —— 不要停下来问「要不要做成 HTML」「要不要我加个演示」。用户要的是打开就能看的东西，不是问卷。

*只有一种情况该问：用户只丢了一个词或一句话，连主题边界都判不了（没给材料，也没说想懂什么）。*

*判据：能说出「读者会用哪句话转述」。说不出来就自己先定一个，写在页面第一句里 —— 定错了改一句，比问一轮便宜。*

**第一屏就是最核心的那一屏。** 不是「先做个雏形给人看」，而是成品的第一屏必须自己站得住；后面的段落再逐层展开。

## 步骤

1. **判形** —— 这东西是线、是网、还是过程？*判据：能说出停在哪档、以及为什么不再上一档。*
2. **文字先行** —— 不管升到哪档，对话里先给结论；L1 就地把话重写干净。*判据：只看对话就拿到答案，文件是加分项。*
3. **按档产出** —— 见下两节。*判据：产出自包含（无外链 / CDN / 网络字体），拔网线也正常。*
4. **交付** —— 绝对路径 + 打开方式 + 一句「怎么用」。*判据：用户不问「文件在哪、怎么看」。*
5. **不要用问题结尾** —— 交付完就结束，不要附「要不要我再做成 X」。想做什么就顺手做进同一份文件里。

## 展示台：先找现成的骨架

L3/L4 的产出不必每次从零搭。这几套骨架覆盖了绝大多数「把结果摆给人看」的场合，**能套就套，套不上再自己写**。

| 内容形状 | 骨架 | 关键交互 |
|---|---|---|
| 要用户勾选 / 复制指令 | `~/.pi/agent/templates/decision-deck-template.html` 决策台 | 卡片多选 + 实时拼提示词 |
| 已定结论的排名 / 倍数 / 占比 | `templates/showcase-board.html` 方块榜 | 方块数即数值 + 基准虚线 |
| 有因果或时间顺序 | `templates/showcase-narrative.html` 叙事 | 时间轴播放 + 每幕重放动画 |
| 有参数可调、结果跟着变 | `templates/showcase-dashboard.html` 仪表盘 | 滑杆 → 实时重算 |
| 谁连着谁，且节点细节多 | `templates/showcase-topology.html` 拓扑 | 点节点出详情 + 请求沿链走 |

**套用规则**

- **先看形状，不看名字**。榜 / 叙事 / 仪表盘 / 拓扑四者不重叠：选错比从零写还慢。
- **能套就套**：复制到产出目录，只改数据区 + 文案，保留动效层。每个骨架文件头有「几处要改」，先读那 30 行。
- **套不上就自己写**，别把内容硬塞进不合适的骨架。但自己写的也必须带动效和交互 —— 值不值得动，看内容有没有「因果 / 可调 / 关系」。
- 展示页默认写到 `~/workspace/viz/`；用户指定则以用户为准。

**别被自检第 1 条误伤**：那条「不要做成仪表盘」针对的是**讲解型**页面；展示台是**呈现型**，本来就该有图表、数字和轨道。

## 图：工具与尺寸

| 要画的图 | 用哪个 |
|---|---|
| 单链 3–6 节点、标签能用英文 | `diagram`（D2），一次调用 |
| **中文标签**，或**任何并列 / 分叉** | `svg-mcp` |
| 对照 / 枚举 / 状态矩阵 | markdown 表格 |

D2 的两个硬限制：**中文标签必崩**（字符按宽度 1 计，实际占 2，框线必错位）；**只支持单链**
（两个节点并排就崩）。`svg-mcp` 没有这些限制，代价是多几次调用：

```
create_document(width, height)
add_diagram_graph({nodes:[{id,label,kind}], edges:[{from,to,label}]})   # 自带分层布局
render_document()   # 自己看一眼
export_render(format="png" | "svg", path=...)
```

节点 `kind` 用 `service` / `datastore` / `note` / `decision`；`label` 里的 `\n` 会换行。

**尺寸按手机定**（图主要在手机上看）：竖版优先，画布宽 400–560，字号 ≥11px；宁可拆两张；
要出宽版（电脑 / 幻灯片）先问一句。画布给太大会让图缩在角落（内容区 640×180 → 画布 780×250 正好）。

**图崩了不要退回段落** —— 换工具或换标签语言重试，一次尝试的成本远低于丢掉结构。

## 送达：必须用 write

pi-web 只把 **`write` / `edit` / `apply_patch` 调用过的路径**当附件卡片。`bash` 里的
`cp` / `sed` / `python` 造出来的文件不会有卡片 —— 只有一行路径，用户手机上点不开。

- **`.html` / `.svg`（文本）**：`write` 直接写成品。一次到位，别走「bash 生成 → read → write」（白花一倍 token）。
- **PNG / GIF（二进制）**：`write` 写不进去，要两拍 —— ① `write` 一个同路径的占位文件（作用是**登记**路径，
  不是写内容）② 真工具（如 `svg-mcp export_render`）把该路径**覆盖**成真图。**顺序不能反**。
- 附件只挂在**含该调用的那条消息**上：每轮都要重新登记，历史消息不会追溯补。

*判据：用户回「看到了」，而不是你又丢了个路径给他。*

## 交付前自检（L3/L4）

逐条对着实际产出过一遍，别凭记忆。发现就打回去改，不留「下版再说」。

1. **文章，不是仪表盘** —— 没有 KPI 大数字卡、指标网格、状态徽章、彩色 callout、满页圆角卡片壳。正文驱动理解，图服务叙述。*判据：换个话题这套设计几乎不用改，就是太通用。*
2. **打开就有东西看** —— 没有空白画布，没有「点击开始」。默认状态就在演示那个现象。
3. **默认值夸张到现象可见** —— 教学清晰度优先于真实；读者能调小，看不出就学不到。
4. **慢到能看清因果** —— 动画放慢；循环演示干净复位，不继承上一轮的累积状态。
5. **视觉语言全场一致** —— 同一变量同一种颜色；半径画成虚线圆，每张图都是虚线圆。

正文本身也要过关：无堆砌破折号、无「不是 X 而是 Y」的否定翻转、无结尾大总结。改法见 `references/anti-slop.md`。

**验证不靠眼睛猜** —— 横向溢出、JS 语法、外链清单、移动端表格，都有确定性检查；具体命令见 `references/visual-baseline.md` 末尾。
