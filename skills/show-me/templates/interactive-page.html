缓存不是加速，是取消

它没有让传输变快 —— 它让传输不需要发生。搞清楚下面两个字段和一个状态码， 网页缓存九成的现象你都能自己推出来。

一句话

浏览器手里有一份本地副本。每次要资源时它先问自己：这份还能直接用吗？ 能就一个字节的网络都不走；不能确定就去问服务器「变了吗」，服务器说没变， 那份副本继续用。

所以缓存省下的是往返和正文，不是带宽峰值。它取消的是请求本身。

两个头字段

字段谁发的它说什么过期后
Cache-Control服务器 「max-age=3600」= 一小时内别来问我 浏览器进入协商流程
ETag服务器 「"a1b2c3"」= 这份内容的指纹 拿去当暗号对

max-age 管的是「不用问」，ETag 管的是「问的时候怎么答」。 两个一起用才有完整效果。

状态码对照

状态码含义正文你该做什么
200新内容，拿走吧有，完整替换本地副本
304没变，用你手里那份空什么事都没有
404没有这个资源有，错误页别缓存错误页

304 是这套机制的省力点：头部几十字节换掉整份正文的传输。

一次完整走法

# 第一次
GET /logo.png
→ 200 OK
  Cache-Control: max-age=3600
  ETag: "a1b2c3"

# 一小时内再访问
（浏览器直接用本地副本，没有任何网络请求）

# 一小时后
GET /logo.png
If-None-Match: "a1b2c3"
→ 304 Not Modified
  （正文 0 字节）

四个常见坑

静态资源给了 max-age，却没加内容指纹

文件名不变、内容变了、缓存又没过期 —— 用户会一直拿旧文件。封面图改动后线上没生效， 八成是这个原因。

做法：文件名带上内容哈希（app.7f3a91.js），配合长期 max-age。 内容一变文件名就变，缓存永远不会撞车。

用 no-cache 以为是「不缓存」

它其实是「可以存，但每次都要问服务器」。真要不存，写 no-store。

把 304 当成出错

304 是成功的，只是没有正文。日志里看到大量 304 说明缓存工作正常。

给接口也配上长缓存

接口返回的是数据，会变。数据类响应一般用 no-store 或很短的 max-age， 只有真正的静态资源才适合长缓存。
