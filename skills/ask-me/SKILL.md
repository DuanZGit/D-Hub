# ask-me

本机 88 个技能里，低频的那些被设成「显式」省上下文 —— **模型自己看不见它们**。
本技能是这批技能的入口，也是全部技能的总目录。（`ask-matt` 讲的是 Matt 那套工程流程，不是一回事。）

## 1. 扫描并同步（每次运行先做，别凭记忆）

```bash
python3 <skill-base-dir>/scripts/scan_skills.py --check-index
```

`<skill-base-dir>` 是本文件所在目录。脚本只读。三件事按顺序：

**① 看全量。** 名称、`[自动]`/`[显式]`、描述。`--grep 词` 粗筛，`--roots` 看扫描根。
**别用系统提示里那份列表** —— 它只有自动技能，漏掉的正是要捞回来的那批。

**② 补索引。** `--check-index` 报出的未登记项，**直接补进 `~/.agents/skills/INDEX.md`，不用问**：
按现有分区加一行（技能名 / 触发场景 / 核心能力）。索引落后就等于没有。

**③ 报名单漂移。** 干跑 `python3 <skill-base-dir>/scripts/apply_modes.py`，它列出不在 KEEP_AUTO 里的技能。

名单的判据是 **「这技能需不需要模型主动触发」** —— 不看频次，不看装了多久：

- **需要**：用户会说需求但不会报技能名（「画个架构图」「做个云南攻略」）→ 必须在名单里，
  否则永远不会被想起来。
- **不需要**：用户自己会打名字（DK、gushen），或只在特定场合点名 → 降为显式。

**升降级要用户拍板**，但装完就该判，别拖。

*完成判据*：`--check-index` 无未登记项；名单漂移已报告或已确认。

三步做完再路由。**按任务逐条核对描述，不确定的直接 read 那个 SKILL.md** ——
80K 候选上的实测：只看名称+描述会让路由准确率掉 37–44 个百分点。

## 2. 判定任务

先从会话上下文推断；不够才问，且只问一句。画像写清：**做什么、产出什么、在哪**。

## 3. 筛选三关

- **同词不算**：「设计一张数据库表」不推 `design`（那是视觉设计）。
- **前置不满足不算**：要 key / 要远程 / 要未装 CLI 的，先说缺什么。
- **重叠不等于互斥**：多个技能命中同一触发词时，**先研究这次的情景**再定 ——
  是其中一个更贴、两个各管一段（串联），还是都上。

判据是「这次的产出需要哪几种能力」，不是「哪个更厉害」：

| 情景 | 判断 |
|---|---|
| 「画个架构图」 | `fireworks-tech-graph` 出技术图；若要求统一风格 + 可校验，`svg-diagram`；只要快速看一眼结构，`diagram` |
| 「做个云南攻略」 | 多日 + 要 PDF → `trip-planner`；周末两日、要手机上看的路书 → `jianhao-travel-planner`；两者可串联（先定行程再出带版式的路书） |
| 「把这东西讲清楚」 | 看要的是对话里的图（`svg-mcp`）还是能发出去的讲解页（`show-me`） |

**候选都摆出来比，不要因为名字像就草率砍掉一个。**

## 4. 输出

三档，一行一个，按执行顺序：

```
Primary     必用
  d-reach                      搜网站并抓正文            <skill-base-dir>/SKILL.md
Supporting  配套
  ponytail                     写码时压代码量
Optional    用户说了才做
  show-me                      要讲解页才做
```

**每个都要带 SKILL.md 绝对路径** —— 显式技能不在系统提示里，没路径就读不到正文。这是本技能交付的核心。

末行给最短路径：`d-reach → ponytail → code-review`。

## 5. 收尾

问一句「要我现在按这个顺序开始吗」；说要就直接做。汇报时带一句**这次同步了什么**。

## 两个脚本

| 脚本 | 读写 | 范围 |
|---|---|---|
| `scan_skills.py` | 只读 | 全部 6 类根（用户级 + 项目级 + pi 包内） |
| `apply_modes.py` | **读写** | 只碰 2 个用户级根 |

范围不同是故意的：包内 SKILL.md 属于上游，`update` 会覆写，脚本不该去改。

`apply_modes.py` 的安全规则（默认干跑 / 写前快照 / 写完自验 / 失败整批回滚 / 越界不写）
写在它自己的头部注释里 —— **改它之前先读那里**。

## 自检

```bash
bash <skill-base-dir>/scripts/selftest.sh     # 17 条断言，跑在假技能库上，不碰真实技能
```

**改过 `apply_modes.py` 后必须跑**：它对 74 个真实技能文件有写权限。

## 边界

- 只有一个技能能覆盖 → 直接说，别硬凑三档。
- 一个都没有 → 明说「本机没有覆盖这件事的技能」，别拿相邻的充数。
- 推的是 `[显式]` 技能 → 提一句用户下次也可以 `/skill:名字` 直接调。
